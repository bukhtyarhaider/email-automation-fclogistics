# Outreach Desk 2.2.0-rc.8 — reviewed imports and carrier conversations

Feature branch: `feat/import-repairs-carrier-conversations`.
Previous stable build: 2.1.0. This is a release candidate for review, not an automatically approved production deployment. Experiments 01–03 are integrated into the normal app; Team work remains on `feat/sales-experiments` and is excluded from this candidate.

## What is integrated

Run the normal launcher or `npm start`; use the normal sidebar. There is no separate experiment server or login system in this workflow.

- **Leads Workspace → upload XLSX → Import review & repairs.** New browser uploads are paused and require a reviewed revision before outreach. Existing campaigns keep their previous state and sending behavior. The advanced local-path `/api/import` endpoint retains its established import behavior; its mappings can subsequently be reviewed through the same sidebar.
- **Import review & repairs.** Inspect headers and bounded source samples, select company/email/Status columns with dropdowns, or use advanced JSON. Add a Status header only in an entirely unused column. Preview the exact proposal, record source provenance, then save it. Status may not point to company, operating status, USDOT or another mapped field. Custom outreach columns must have an explicit Status/outreach-status label.
- **Activate a selected revision.** Stop outreach and close the prepared composer first. Activation validates workbook/identity hashes, retains old contact protections, creates a separate campaign working workbook and durably switches the campaign pointer. The campaign stays paused. Inspect its leads and explicitly enable it in Campaigns when ready. Original uploaded workbooks and immutable revision copies are retained.
- **Undo last activation.** Restores the previous workbook pointer, mapping and review metadata while keeping outreach paused. It checks that the retained previous workbook is unchanged. Send history, suppression and saved revisions are not rolled back. An earlier reviewed revision may also be activated as a new working copy; retained history/protection guards prevent it from making previously contacted addresses new again.
- **Carrier identity & source.** Activated imports attach stable carrier/contact IDs and row-level provenance to normal lead details. Consistent source USDOT identities group across campaigns within this PC’s workspace. Missing/conflicting/layout identities remain provisional or unresolved. IDs are source evidence, not FMCSA verification.
- **Carrier conversations.** Shares the existing app shell. Exact message references and participant checks match replies to confirmed local sends; uncertain or subject-only evidence requires explicit review. Original sends and captured messages are shown as escaped plain text. Links from lead details and Send History search this inbox for the contact. No reply is sent by this screen: use the existing mailbox for responses.
- **Protection in the real sender.** Captured definite opt-outs immediately guard normal outreach, appear in the regular Do Not Contact state and survive restart. The sender checks the guard again immediately before clicking webmail Send. There is no automatic resend after uncertainty. A capture-storage fault blocks outreach until a successful durable recovery. Category edits, ignoring a message and revision restoration never erase captured opt-outs.

## First-use walkthrough

1. Back up this PC as described below, then start the candidate against the intended workspace after review approval. Existing campaigns need no automatic conversion.
2. Upload a workbook from Leads Workspace, or open Import review and select an existing campaign.
3. Choose **Review saved mapping**. Inspect raw headers/samples and any layout/missing-status issues. Choose columns, optionally add a new Status header, then **Preview changes**.
4. Enter where the leads came from; keep acquisition/permission unknown if not established. Check the save acknowledgement and **Save reviewed revision**. This saves a copy only.
5. Select that revision and **Use selected revision for campaign**. The confirmation explains the paused state and retained copies. A changed campaign/workbook requires refresh/review rather than overwriting newer work.
6. Inspect normal lead details for identity, source evidence and exclusion reasons. The existing Active/out-of-service/hidden/status/duplicate/history checks still apply; a repaired mapping alone does not make a prospect eligible.
7. Enable the campaign in Campaigns only when its scope and eligible records are correct. Resume sending through the existing prepare/review/send or continuous workflow.
8. Open Carrier conversations. Open **Mailbox tools** → **Capture & mailbox setup**. Without a live connection, **Load local sent history**, then import an authorized `.eml` export under its actual mailbox. Choose the mailbox recorded on the tool’s confirmed sent history. Imported contacts alone do not qualify. Inspect the match/category, enter review notes and explicitly link uncertain messages only with evidence.
9. Test Undo last activation in a stopped workspace. It must restore the prior workbook and keep outreach paused without clearing history or opt-outs.

## Live mailbox setup

Conversations → **Mailbox tools** → **Capture & mailbox setup** → **Read-only mailbox capture settings** stores only nonsecret metadata on this PC: account email, login user, IMAP host, Inbox/Sent folders, full-history/all-folders options, page limits, backfill date, batch size and credential environment-variable names. Add up to 20 authorized mailboxes. TLS port 993 is required. Blank Sent folder uses the provider’s special-use Sent folder when available.

Put credential values in this PC’s private `.env` file and restart through the normal launcher. For example, a mailbox can reference `REP1_IMAP_PASSWORD`; the secret itself is never entered in mailbox JSON. OAuth uses `accessTokenEnv`. Gmail/Yahoo password access requires a provider-approved app password mode; Outlook requires OAuth. This build does not enroll or refresh provider tokens. Use the provider’s legitimate authorization process.

Enable capture after checking the explicit read-only authorization box. **Scan previous replies** checks all available history and selectable response folders (excluding Drafts), even if the automatic sync has a narrower date/folder scope. It continues past the automatic page limit, with saved progress and a Stop scan button. Pages alternate between Sent, Inbox and other folders so a large Sent backlog does not delay every incoming response. Bounded metadata batches reduce network round trips; batch failures fall back to the same per-UID checks. Already-known original sends retain their tool body, while missing bodies can be recovered from read-only Sent evidence. Resume by pressing the scan button again. A run uses up to fifteen minutes of work and up to eight cross-folder ancestry passes; larger or interrupted work is labelled Incomplete or Stopped and remains resumable. A finished folder search never becomes a claim that deleted/provider-expired mail was recovered.

Sent is checked first to recover original tool Message-IDs from tracking evidence. The scan then checks Inbox and available archives/All Mail/Junk/Trash when the provider exposes them. It revisits earlier folders if later messages reveal a parent reference. Each folder has a stable high-water UID for that pass so newly arriving mail cannot keep a pass running indefinitely. Expunged messages are skipped only after disappearance is verified. Failed fetch/storage retains the failed cursor; successful pages remain saved. UIDVALIDITY, source-scope and new confirmed send changes cause appropriate rescans with deduplication. A misconfigured Drafts folder is excluded and produces incomplete coverage.

Automatic checks retain their configured date, folder scope and 1–10 pages per folder/check, with 1–100 messages per page. They use stable source anchors so learning a reply does not repeatedly reset the incremental backlog. Due accounts are checked by the scheduler; successful checks wait at least sixty seconds and failures back off. Manual historical checks bypass that cooldown. Setup settings override `FC_REPLY_CAPTURE_ENABLED`, `FC_REPLY_AUTO`, `FC_REPLY_MAILBOXES`, `FC_REPLY_SINCE`, `FC_REPLY_BATCH`, `FC_REPLY_ALL_HISTORY`, `FC_REPLY_ALL_FOLDERS` and `FC_REPLY_PAGES`. Experiment flags never enable normal capture. Live capture defaults off; delivery/bounce monitoring keeps separate settings/cursors.

**Tool-started conversations only:** the anchors are this PC’s confirmed send history and non-seed tracking records with confirmed tool submission. Older tracking sends remain available when a later history entry exists. Legacy app history marked Sent is retained with its original provenance; an imported workbook Status, imported contact, subject similarity or arbitrary mailbox Sent message does not create a tool-send anchor. Known-contact messages without a reliable reference, aliases, changed participants, reused IDs and unavailable bodies enter matching review where related tool-send evidence exists. They are not counted as confirmed human responses until matched/reviewed. An imported-only inbound conversation from an earlier candidate is excluded from the current inbox; retained evidence, drafts and opt-out protections are not deleted. No new inbound-only conversation can bypass the tool-send requirement.

Capture opens folders read-only and never marks, moves, deletes or sends messages. Full bodies over 2 MB become review stubs, and the new-text view is bounded to 24,000 characters. Attachments and unsupported quote/provider formats require original-mailbox inspection. Coverage depends on retained source evidence and provider access/retention; other PCs’ histories and private mail are not automatically synchronized. Header dates are sender-reported, capture times are separate, and counts do not establish conversion, delivery or human reading. Manual Send History review remains a separate assertion.

## Reply desk and tracking

The default **Carriers who replied** queue shows matched human responses. **All tool-sent conversations** also includes those with no captured reply. Each responded thread shows a reply count and first/latest reply dates; the contact count uses unique email addresses within the mailbox/search scope, not verified carrier entities. This label never proves silence; inspect capture coverage and the mailbox. Separate queues cover **Needs my reply**, **Follow-up eligible**, **Interested**, positive/negative responses, missing details, unread evidence and drafts needing approval. Dashboard highlights link directly to the affected conversation or matching review. Read/unread is this PC's review marker; it does not change provider read flags or synchronize between salespeople.

Intent uses transparent local language/header rules and operator-reviewed categories. Pricing questions stay separate from confirmed interest, mixed signals require review, and automatic/OOO/bounce messages are separate from human replies. Rules can miss nuance; inspect the displayed source and correct its category. There is no external AI call, lead scoring guarantee or signed-carrier claim.

1. Open the original message evidence and review its match/intent. New contact messages or changed senders/references that need matching block draft approval. A manually linked message with a different sender stays held for address review.
2. Open **Carrier details & source evidence**. Phone, equipment, ZIP, name, truck count, USDOT/MC, availability and lanes are candidates. Select carrier-stated values and confirm their exact source, or cite an exact quote for an extractor miss. Missing data is asked in the suggested response. Conflicts keep earlier evidence; an explicit current review resolves the displayed conflict, and later changed evidence requires another review. These confirmations do not verify phone ownership, location or authority and do not silently overwrite workbook identity.
3. Write directly in the empty reply editor. **Need a starting point?** and **Use saved wording** open a preview without changing the draft. Search saved replies, then deliberately Insert at cursor or Replace reply; existing text requires acknowledgement before replacement. Edit freely and **Save draft**. The manager supports search, field insertion, edit/archive, a new copy and retained versions; stale editors cannot overwrite newer wording. Untouched built-in starters migrate to short replies while custom/archived wording and already-approved draft bodies are preserved. `next_question` (and the older `confirmation_questions` field) asks one useful missing detail rather than requesting everything already stated by the carrier. Missing factual placeholders require reviewed/configured values. There is no external AI call or invented rate/guarantee. Unsaved text survives in-app navigation but not browser reload.
4. Choose **Review reply**, then review the exact body, carrier address, sending account and source. Enter an approval note and check the acknowledgement before **Approve this exact draft**. New messages, matching/category changes, detail/source changes, protection changes or text edits invalidate the previous approval. When coordinator team mode is enabled, creating/approving/copying a draft requires a successful current coordinator check; shared opt-outs and uncertain submissions hold it. Cold-outreach deduplication alone is not a ban on answering a carrier. Cancel a saved draft/approval to withdraw it while keeping history. Earlier edited bodies and approval hashes remain retained.
5. **Copy approved reply**, then **Open my mailbox**. Open the actual carrier thread, use native Reply, paste above the existing signature and click Send yourself after the mailbox's final recipient/account review. The app does not create or submit a mailbox message, and cannot enforce edits you make outside it. A copied draft cannot be remotely recalled. There is no automatic conversation-send endpoint.
6. After manually sending, optionally **Record my mailbox action** with evidence. This is an operator report, not verified submission/delivery. Read-only capture separately labels a matching approved-body prefix in the Sent folder (at least 20 characters, same matched thread/participants, provider header time at/after approval with a five-minute tolerance). Inspect the original copy; matching is not delivery proof. Later inbound messages reopen reply attention.

No-response follow-ups default to at least three waiting days after the latest known outbound activity across this contact’s local tool threads and a maximum of one reviewed follow-up. Adjust to 1–30 days and 1–3 follow-ups in the library. A reply in another local tool thread prevents an old-thread no-response follow-up. An unfinished historical scan must finish before a proactive follow-up. Only no-captured-human-response contacts are eligible; automatic/OOO/unresolved/ignored inbound evidence, opt-outs, source holds and uncertain submissions prevent proactive follow-ups. Eligibility generates a draft only; it never schedules a send. An answered carrier message uses the response workflow instead. Declines do not enter proactive follow-up; an optional manual acknowledgement still requires approval, while opt-outs block all drafts.

Storage and dashboard counts are local to this PC. They do not establish which of the five salespeople owns a reply across separate installations. The deferred Team work experiment remains excluded. Keep capture configured for every intended mailbox and retain each PC's own data/configuration.

## Coordinator protection and recovery

When team mode is enabled, captured opt-outs are queued durably for the existing coordinator’s suppression API. Local protection does not wait for network success. Retry runs immediately and on the regular scheduler; acknowledgements are saved, and an interrupted acknowledgement is safe to replay. The inbox shows pending delivery. Keep the coordinator connected and inspect pending items before assuming another PC is protected. Independent-PC mode cannot protect another machine remotely. Firebase open-event sync does not share reply bodies or replace coordinator suppression.

An opt-out must remain held unless its underlying permission/evidence has been deliberately resolved. This candidate does not offer a captured-opt-out override: the generic Do Not Contact removal action explains the hold instead of silently clearing it. Correcting a category or ignoring review evidence is reversible, but does not withdraw a recorded opt-out. Full original context remains in the mailbox.

## Storage, backups and rollback

All new production state lives under the existing PC’s data folder. `data/carrier-workspace/` contains immutable workbook revisions, mapping/source records, identity registry, captured plain-text messages, read-only cursors, reply templates, drafts/approval versions, carrier-stated detail confirmations, read markers and review events. Normal `data/state.json` retains campaign pointers, capture settings, suppression and coordinator retry acknowledgements. Secret values remain in `.env`; browser sessions stay in their existing PC-specific folder. The old `experiment-data/` workspace is preserved separately and is not silently imported into production. Re-review an experiment proposal or import an authorized EML through the normal UI when needed.

Before updating, click **Stop outreach**, wait for the current operation to finish and close any prepared message. Then stop this PC’s app and back up **the entire data folder and its own .env**. Retain `team-data` if it hosts the coordinator. Extract the versioned ZIP over application sources, preserve private data/configuration, run Setup when dependencies changed, start and verify the candidate version in Version Catalog. Never copy another PC’s state, browser profile or credentials. No other PC is installed or verified by this package.

To undo a workbook activation, use the in-app action while stopped. To roll back the application version, stop it, restore the matching pre-upgrade data backup and previous application package together. Keep a separate copy of any newer send/reply evidence for reconciliation; never discard post-backup attempts and then restart sending. Immutable revision downloads help recover mappings/source copies; a missing/corrupt current workbook or altered archive needs backup recovery before activation. A failed publication leaves the previous campaign pointer in place; retained files may include an unreferenced interrupted copy, which is never auto-sent.

One process owns a data folder through the existing `app.lock`. The revision/reply archive also uses a flushed atomic writer and `write.lock`; reply scanning has `reply-capture.lock`. After a crash, verify/stop the recorded process before removing only a stale lock. Never delete history/protection files to clear a wait or lock. Interrupted archive writes keep the last published JSON/revision. Malformed saved reply/protection state fails closed rather than treating missing knowledge as permission to send.

No shared filesystem service, public/LAN listener, account/ownership workflow, automatic retention/archival, production sequence sender or cross-PC inbox is added. The existing local host/origin/CSRF protections remain. Back up the full workspace; larger inboxes need storage/retention planning before long-running team deployment.

## Carrier history and daily workflow (rc.6)

- **Active** separates carriers already in conversation, including contact history awaiting thread review. **Needs reply** shows unanswered carrier messages; **All** lists one carrier per mailbox/email with confirmed tool outreach; **Waiting** means no captured human reply. **In review** groups workflow reviews and latest unlinked messages. Under Filters, choose individual tool threads to inspect the earlier per-thread view. The badges use the current mailbox/search scope, and additional category/work filters are available in **Filters**. A selected conversation remains visible when it falls outside new filters, with an explicit note.
- Search by sender, company, subject or captured wording. Latest effective message times order the inbox; header dates are sender-reported and future/invalid dates use bounded capture time. Header display names are conveniences, never identity verification.
- Select a carrier to read the latest message and write a reply immediately. **Earlier emails with this carrier** expands the earlier captured chains. **Details** contains the complete captured contact history and original tool sends, message matching/classification review, local read/unread controls and source-backed carrier details. The original mailbox is the authority for complete context.
- **Help with wording** and **Saved lines** preview optional wording without creating a draft or replacing your text. Insert at your cursor or deliberately replace the reply. **Manage saved replies** opens the searchable versioned wording library. Saved custom wording is retained.
- **Save draft** is available for unsaved edits. **Review reply** also saves your current edited text before opening the exact-text/account/recipient approval dialog. Approval needs an explicit checkbox and note. New evidence, holds, edited wording and changed versions block approval/copy. Closing the review does not approve or send.
- After approval, copy the approved text, open the existing mailbox and use native Reply above its signature. Record a mailbox action only after you send it yourself. Operator reports, matching Sent copies and delivery remain different evidence.
- Unsaved draft text survives switching queues, searches and conversations in the running page. Reloading/closing the app discards unsaved edits; use Save draft to persist them. On narrow screens use **Back to inbox** to choose another carrier.

Carrier conversations shares the established header, sidebar, mailbox profile footer, developer information, notifications and responsive navigation with every other route. Only the conversation workspace has its own content layout. The sample preview uses isolated synthetic data with sending and live capture disabled; production provider/other-PC rollout remains a separate acceptance step.

## Reuse an existing mailbox login

Signing in through the sender's browser profile is separate from IMAP inbox capture. If this PC already has `FC_IMAP_USER` / `FC_IMAP_PASSWORD` or a delivery-monitor mailbox list, open Mailbox tools → capture settings → Existing mailbox credentials. Choose the matching saved profile and **Use existing mailbox setup**. This copies nonsecret host/account/folder settings and credential variable names into the form. Enable capture, authorize read-only access and Save capture settings, then scan. Other profiles are not guessed from this login, and credentials are never returned in API/UI responses.

A sample preview explicitly disables provider capture. Use the normal app window and its own local data directory to see real sends/replies; the sample preview does not share customer data or profiles.

## Carrier status and follow-up

Open **Carrier status** to choose Waiting, In review, Active conversation, Follow up, Signed or Closed. Save a note and, for Follow up, a date/time. These are local workflow records with stale-update checks and retained changes. They do not schedule outbound messages, assert a signing from email sentiment, or remove protections. New incoming evidence reappears for attention even after a carrier was closed. Use **Mark history read/unread** to track the latest displayed carrier evidence.

History is scoped by a confirmed tool send to the exact carrier address in the receiving/sending mailbox. Once that scope exists, earlier chains with the same participants can appear as contact context even when their subjects/references differ. This does not establish that every earlier relationship was generated by the tool. Imported-only contacts and unrelated addresses remain excluded. Unknown/changed participants, oversized bodies and reused Message-IDs remain explicit review cases. Earlier ordinary unlinked context does not block a newer matched reply; an unlinked latest message must be reviewed before drafting. Draft approvals are invalidated by new contact evidence across threads, and reviewed independent chains retain their own reply subject.

## Conversation reliability refinements (rc.7)

Dashboard attention is selected across the full carrier backlog before pagination. Closed/Signed labels clear the reply task until new incoming evidence arrives; a new reply remains explicitly marked. Incoming and outgoing messages sharing a header second use the same stable order as the reader. Recent exact-participant native Sent history postpones no-response follow-up eligibility and counts toward the follow-up maximum even without thread references. Workflow dates remain reminders, never scheduled email sends.

Unsaved carrier status edits remain associated with that carrier while navigating in the running page. They retain the version originally edited: a refresh cannot silently authorize overwriting another window's status or new evidence. On a conflict, edits stay visible. **Reload saved status** deliberately discards the unsaved status form and loads the saved stage/date/note before a new edit. Browser reload still discards unsaved edits; save first. Read/unread controls show the next available action after each update. Internal scan IDs are reserved so custom mailbox IDs cannot overwrite history progress.

## Direct read controls (rc.8)

On the dashboard, each carrier alert with an incoming message has **Mark as read** beside Review. The latest incoming message in Conversations has the same direct action below its sender. Both switch to **Mark as unread** after saving. Existing history/details controls remain available. Read state is shared between these views on this PC; it does not change provider mailbox flags. Earlier messages do not have a button that could accidentally mark a newer reply read.

The unread count/highlight updates immediately. Marking read does not close a reply task, approve a draft or send email. New carrier evidence returns the conversation to unread. Requests bind to the displayed message/version, so newly arriving evidence cannot be silently cleared by an old action. Saving/error feedback is visible, edits are retained, and desktop/mobile controls use the existing design.
